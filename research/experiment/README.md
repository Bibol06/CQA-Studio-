## Что проверяем дальше

**Гипотеза:** обязательная привязка к доказательствам уменьшает число неверных оценок по сравнению с обычной оценкой по тому же чек-листу.

- A: оценка и объяснение, без обязательных цитат.
- B: те же инструкции и чек-лист плюс обязательные ID сообщений и цитаты; для пропущенного действия — проверенный участок, для N/A — обоснование неприменимости.
- Одинаковая модель, её версия и настройки. Первоначально по одному запуску на диалог/вариант. Порядок A/B чередовать, чтобы меньше зависеть от нагрузки сервиса.
- 6 диалогов для настройки и 6 для локальной проверки — точные ID в `frozen_manifest.json`. Это не контрольные данные организаторов.
- До просмотра ответов модели согласовать спорные оценки с человеком. Текущая разметка создана ассистентом и не подтверждена независимо; совпадение с ней не означает точность относительно жюри.
- Из сравнения по критериям исключаются 17 строк `needs_review=true`. Все остальные строки тоже остаются предварительными; особенно не подтверждены внешним справочником факты по К4.
- После реального подтверждения разметки создать новую версию эксперимента: текущая версия фиксирует исходную разметку, её нельзя незаметно менять.

## Как использовать задания

`requests.jsonl` — одна строка на задание. Поля:

- `request_id`: идентификатор результата, например `p1-ru-022__B`;
- `split`: tuning или validation;
- `system_prompt`: полные инструкции с официальным текстом чек-листа;
- `input`: диалог с исходными ролями, временными метками и добавленными номерами сообщений.

Передать `system_prompt` и сериализованный `input` выбранному сервису модели. Вход не содержит текущих эталонных оценок. API организаторов предоставляет только диалоги; его URL не является адресом AI-сервиса.

В `response_template.json` показана оболочка для сохранения ответа. Это пустой пример, а не результат. В `response.criteria` нужно сохранить восемь реальных ответов модели. Каждый результат — отдельной строкой JSON в `responses.jsonl`. Записывать фактическое название модели, время и использование токенов; не выдумывать стоимость или отсутствующие данные usage.

## Команды

Использовать Python с установленным pypdf. В этой среде подходит Python из Codex Primary Runtime; дополнительных библиотек не требуется.

```text
python ../experiment.py prepare --live
python ../experiment.py test
python ../experiment.py evaluate --responses responses.jsonl
```

Команды показаны для текущей папки `research/experiment`. Сам скрипт определяет пути по своему расположению. `prepare --live` читает ссылку из Student Guide и выполняет GET; он не вызывает платные модели. Секретную подпись API не печатает.

`evaluate` создаёт `comparison_results.json` только после передачи результатов модели. Он проверяет структуру ответов, пересчитывает балл кодом, сравнивает разрешённые критерии с предварительной разметкой и проверяет существование цитат по ID сообщения. Он отмечает отсутствие доказательств, но НЕ проверяет автоматически, доказывает ли цитата вывод по смыслу — для этого нужен отдельный просмотр.

Вывод о гипотезе делать только после заполнения обеих половин A/B. На 6 отложенных диалогах вывод будет предварительным: обязательно показывать числа ошибок и размеры выборок, а не только проценты. Для полноценной проверки дополнительно нужны раздельные метрики N/A, грубых ошибок и шкал, семантическая проверка доказательств и затем контроль организаторов.
