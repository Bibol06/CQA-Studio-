# Запуск и проверка проекта

## Быстрая локальная демонстрация без ключа

Нужен Python 3.11 или новее. Распакуйте архив в отдельную папку. На Windows запустите `START_DEMO.cmd`, затем откройте `http://127.0.0.1:8766`.

То же из терминала в корне проекта:

```powershell
python demo/prepare_demo.py
python server.py --port 8766 --db data/public_demo.sqlite
```

Будут загружены три синтетических чата RU KZ EN. Они не являются данными организаторов или результатами модели. Работает ограниченный режим правил: часть смысловых критериев не оценена и общий балл может отсутствовать. Можно проверить карточку, фильтры, редактор, очередь и апелляцию. Официальные результаты этой локальной демонстрацией не заменяются.

## Проверка на данных организаторов

```powershell
python server.py
```

Откройте `http://127.0.0.1:8765`. Через «Загрузить данные» импортируйте официальный JSON, затем в «Настройки модели» укажите провайдера, доступную модель и собственный ключ. Ключ хранится в памяти процесса. Для Gemini поддержан native audio API; основная текстовая оценка поддерживает также OpenAI, совместимый API и Ollama.

Запустите проверку одного диалога, дождитесь задания в очереди и проверьте цитаты, N/A и расчёт. В текущей рабочей базе автора сохранены все 65 оценок; эта частная база не входит в публичную поставку.

## Проверка официального файла без частной базы

```powershell
python jury/check_package.py
```

Скрипт проверяет SHA-256 поставляемых файлов, схему, 65 ID, каналы, допустимые значения, границы evidence_turns и арифметику DEV. В текстовых файлах перед хешированием CRLF приводится к LF, чтобы обычный Git checkout не считался изменением содержания; PDF проверяется по исходным байтам. Для границ используется опубликованный индекс ID и количества реплик. Он не содержит сам текст: **смысловую правильность и точное соответствие источнику такая переносимая проверка не доказывает**.

При наличии оригиналов в локальной базе доступна полная проверка:

```powershell
python -X utf8 submission.py check results/dev/results.json --set dev
```

## Автоматические тесты

Полный Python-набор включает дополнительные аудиопакеты. Для воспроизведения полного набора:

```powershell
python -m pip install -r requirements-asr.txt
python -X utf8 -m unittest discover -s tests
node --test tests/*.test.cjs
```

Node нужен только для тестов JavaScript, не для запуска сайта. Обычные проверки используют заглушки внешней модели и не требуют ключа. Реальные эксперименты описаны отдельно; их повтор расходует доступную квоту.

Для самой локальной ASR-модели дополнительно выполните `python setup_asr.py`. Пакеты и модель не входят в архив; три файла модели занимают около 104 МБ. Результаты распознавания не измеряют точность без ручного эталона. Полная инструкция — [ASR_PIPELINE.md](../docs/ASR_PIPELINE.md).

## Контроль перед отправкой

Проверьте публичность репозитория и финальный commit. После получения контроля нужны оба файла `results/dev/results.json` и `results/prod/results.json`. Нужны реальные десять контрольных ID. Ссылка на Git должна быть передана организаторам; локальная проверка и архив не выполняют эту отправку.

Контроль FBroker уже обработан и опубликован: 10 ok. Для полной проверки в рабочей базе используйте `python submission.py check results/prod/results.json --set prod --group FBroker`. Swap не оценивался. Подробности — [CONTROL_RUN.md](../docs/CONTROL_RUN.md).
