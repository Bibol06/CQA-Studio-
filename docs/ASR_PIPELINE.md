# Независимое распознавание RU/KZ

В звонке доступны три разных инструмента: исходный транскрипт организаторов, читаемая редакция с сомнительными местами и вкладка **«Распознавание»**. Последняя распознаёт сам звук, не получает готовые реплики и позволяет проверить гипотезу «очистка улучшает ASR». Результаты запуска — в [ASR_VALIDATION.md](ASR_VALIDATION.md).

## Как использовать

1. Откройте «Диалоги» → «Звонки», выберите запись, затем справа **«Распознавание»**. Пример: `http://127.0.0.1:8765/?asr=1#p4-ru-001`.
2. В раскрытом блоке Gemini сравните «До обработки» и «После обработки». Для всех пяти DEV-звонков оба варианта уже сохранены; повторный запрос для просмотра не нужен.
3. Прослушайте оригинал обычным плеером. Кнопка «Очищенная копия» воспроизводит первые 20 секунд обработанного сигнала; «Остановить» останавливает эту копию. Обработана вся запись, 20 секунд — демонстрационный отрезок.
4. Раскройте фрагмент Whisper. Его кнопка воспроизводит соответствующий участок оригинала. Метки относятся к файлу, не к ISO-меткам реплик организаторов.
5. Вручную расшифруйте **тот же участок** и введите текст в «Эталон». Для Gemini нужен эталон всей записи, для Whisper — выбранного фрагмента. Сохраните оба языка; не переводите и не исправляйте грамматику говорящего в дословном эталоне.
6. Нажмите «Посчитать WER/CER», затем «Экспорт сравнения и эталонов». Эталон хранится в памяти вкладки; перед перезагрузкой нужен экспорт. Система не подтверждает правильность введённого человеком эталона.

**«Перераспознать: Whisper + Gemini»** создаёт отдельное задание: локальный проход при отсутствии подходящего результата и два облачных запроса. Нужен ключ Gemini. Новый запуск не обучает модель. Редакторская версия и официальный чек-лист не заменяются результатом ASR.

## Реализованный тракт

```text
Запись → проверка файла / SHA-256 → mono PCM 16 кГц
                                 ├─ исходный сигнал
                                 └─ ослабление шума + нормализация
Оба сигнала → одинаковые интервалы ≤29 с → локальный Whisper tiny INT8
Оба сигнала → одинаковый WAV PCM 8 кГц → два отдельных запроса Gemini
            → отдельный результат SQLite → сравнение / эталон / WER и CER
```

Очистка использует STFT: окно 512, шаг 128, десятый процентиль амплитуды по каждой частоте как приближение шума, нижняя граница коэффициента 0,3. FFT выполняется блоками по 20 секунд с контекстом. Нормализация ограничена усилением 10 dB и пиком 0,97. Исходный массив и исходный файл не меняются. Это DSP-обработка, **не RNNoise**; она может повредить тихую речь и отдельные фонемы.

Whisper работает локально через sherpa-onnx, режим `transcribe`, автоматический язык каждого фрагмента, без перевода и подсказки исходным текстом. Минимум энергии между 22-й и 28-й секундами задаёт границу, последний фрагмент не длиннее 29 секунд. Порог энергии исключает очень тихые фрагменты; это не полноценный детектор речи. Отдельный процесс на пару фрагментов освобождает память нативной модели. Кэш различает полные записи и длительности пилота: нормализация зависит от длины сигнала. При изменении обработки нужно менять `VERSION`; очередь проверяет версию готового локального результата.

Whisper tiny — компактная базовая модель для имеющегося компьютера. Его ошибки, особенно в казахском и смешанной речи, заметны при просмотре. Автоматический язык не гарантирует правильное распознавание переключения внутри реплики.

Gemini получает по полному сигналу в каждом запросе. Кодек и частота обеих ветвей одинаковы; исходные реплики не передаются. Промпт требует сохранять RU/KZ, не переводить, не пересказывать и отмечать `[неразборчиво]`. JSON Schema задаёт `text` и `limitations`; сервер проверяет ответ и завершение генерации. STOP — завершение ответа провайдером, **не доказанная полнота расшифровки**. Ошибка видна в очереди, повтор явный. Это аудиовозможность Gemini, не подключение Google Speech-to-Text / Chirp.

## Измерение

WER = расстояние Левенштейна по словам / число слов в эталоне. CER — по символам нормализованного текста. Регистр и пунктуация не учитываются; казахские буквы сохраняются. WER может превышать 100% при большом числе вставок. Пустой эталон даёт отсутствующую метрику, не ноль.

Расхождение гипотез и уверенность LLM не являются точностью. Для проверки нужны заранее размеченные участки: русский, казахский, переключение языков, тихая речь, шум, одновременная речь. Сравнивайте одни и те же слова до/после, отдельно по языкам и смешанной группе. Имена, числа, отрицания и финансовые условия проверяйте по смыслу дополнительно.

## Запуск в новом окружении

Базовый сайт работает без дополнительных пакетов. Для ASR:

```powershell
python -m pip install -r requirements-asr.txt
python setup_asr.py
python server.py
```

Модель скачивается явной командой из публичного Hugging Face с фиксированным revision. Три файла занимают около 104 МБ; дополнительно нужны место для пакетов, SQLite и свободная память. Сборщик проверяет размеры и сохраняет манифест SHA-256; распознаватель проверяет отпечатки перед загрузкой. Модель и локальные данные исключены из Git.

Локальный эксперимент без облака:

```powershell
python -X utf8 asr_experiment.py
```

Он добавляет сравнение к последнему аудиоанализу, сохраняя прежний вариант в `asr_history`. Предварительно нужен аудиоанализ выбранного звонка. Короткий технический пилот: `--ids p4-ru-001 --seconds 30`; это не результат всей записи.

Новые облачные запуски хранятся в `asr_runs`. Официальные оценки, реплики и Results JSON 1.0 не меняются. Ключ — только в памяти сервера. Доверенный режим `CQA_RELOAD_AUDIO=1` обновляет также `cqa/asr.py` перед заданием без перезапуска.

## Для жюри

«Мы проверяем, помогает ли очистка звука русско-казахскому распознаванию. Два распознавателя получают исходный и обработанный сигнал без готового транскрипта. Проверяющий сравнивает варианты с записью и вводит эталон для WER/CER. Система сохраняет оригинал и не переносит догадки в официальный балл. Обработаны пять записей; подтверждённого улучшения точности без человеческого эталона мы не заявляем».

Реализованы DSP, независимые Whisper и Gemini, очередь, сравнение, экспорт и ручное измерение. Chirp, RNNoise и обучение собственной модели не подключены. Django, Redis, Celery, PostgreSQL и S3 для этого локального MVP не требуются: существующие HTTP API, SQLite и очередь выполняют необходимые функции.

Источники: [sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/), [модель Whisper](https://huggingface.co/csukuangfj/sherpa-onnx-whisper-tiny/tree/65176e2deb88badc814a94058666cadccc29b61c), [Gemini audio understanding](https://ai.google.dev/gemini-api/docs/audio), [generateContent](https://ai.google.dev/api/generate-content).
