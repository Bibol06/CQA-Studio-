# Как пользоваться CQA Studio

Откройте http://127.0.0.1:8765. Сайт работает, пока запущен `python server.py`.

## 1. Что находится на экране

Слева — разделы «Диалоги», «Чек-лист», «Обзор качества», «Очередь», «Сдача жюри», «Как пользоваться», ниже — настройки модели.

В разделе «Диалоги» три панели:

1. Список диалогов с языком, запросом клиента и состоянием проверки.
2. Исходная переписка с ролями и временными метками.
3. Результат: итог, резюме, рекомендации, оценки критериев, доказательства и история.

Четыре верхние карточки показывают число диалогов, число полных оценок, средний итог и открытые апелляции. Средний итог — это баллы обслуживания, а не точность AI. Высокий средний балл не означает, что модель правильно оценивает.

## 2. Подключение модели

Откройте «Настройки модели». Для текущего сценария:

- Провайдер: Gemini.
- Базовый URL: `https://generativelanguage.googleapis.com/v1beta/openai`.
- Название модели: точное имя модели, доступной в вашем аккаунте.
- Режим: low для первого эксперимента либо стандартный режим для сравнения. Быстрота и качество проверяются отдельно.
- API-ключ: вставить из Google AI Studio и сохранить.

Ключ не нужно отправлять в чат. Он хранится в памяти серверного процесса, не в SQLite и не в Git. После перезапуска сервера его надо вставить заново; создавать новый ключ при этом не требуется. Обновление страницы браузера ключ не сбрасывает.

При переключении провайдера или базового адреса приложение не отправляет прежний ключ другому сервису. Ключи разделяются в памяти по провайдеру и адресу.

Без модели доступна «Проверка правил». Она формирует только предварительные признаки и оставляет смысловые критерии незаполненными. Такой результат не следует показывать как оценку LLM.

## 3. Загрузка данных

«Загрузить данные» позволяет:

- Получить DEV через API организаторов.
- Ввести `group_id` контрольного набора, когда его объявят организаторы.
- Загрузить JSON-файл или вставить текст ответа API.

Поддерживаются массив диалогов, объект `records` и ответ с `data.records`. Для кнопки API на сервере должен быть настроен адрес организаторов. В текущем локальном проекте он настроен в непубликуемом файле.

Повторная загрузка одинаковых записей не создаёт дубликатов. Если под существующим ID пришёл изменённый транскрипт, импорт отклоняется: прежние цитаты должны продолжать указывать на прежний текст.

## 4. Поиск и фильтры

Поиск ищет по ID и краткому запросу клиента. Фильтры позволяют выбрать RU/KZ/EN, чат/звонок, новые диалоги, результаты с итогом, результаты для пересмотра или грубые ошибки.

«Проверить выборку» использует именно отфильтрованный список. Перед отправкой можно выбрать количество; по умолчанию предлагаются максимум три диалога. Каждый запускаемый AI-анализ — отдельный запрос к модели.

## 5. Проверка одного диалога

1. Выберите диалог слева.
2. Нажмите «Проверить диалог» или «Проверить заново».
3. Приложение добавит задание в очередь и сразу освободит интерфейс.
4. Пока задание выполняется, можно читать другие разговоры, открывать другие разделы и обновлять страницу.
5. После завершения результат появится в карточке. Повторная проверка создаёт новую запись; предыдущая сохраняется в истории.

Модель в одном запросе возвращает ответы критериев, резюме, рекомендации и разбор отдельных вопросов. Код проверяет допустимые ответы и цитаты, рассчитывает баллы и сохраняет результат. В режиме source-turns-v4 модель указывает номера сообщений во всех блоках, сервер проверяет индексы и подставляет исходный текст. Если передана цитата, её точное совпадение всё равно обязательно. Ошибка основного ответа отклоняет новую оценку и оставляет прежнюю доступной. Ошибка только в дополнительном блоке не теряет валидные баллы: интерфейс показывает, какой блок не прошёл проверку. Ошибочный ответ также может расходовать квоту провайдера; автоматических повторов нет.

## 6. Очередь и её статусы

| Статус | Что означает | Что делать |
|---|---|---|
| Ожидает | Задание записано в базу и ждёт свободного обработчика | Подождать; можно отменить |
| Обрабатывается | Запрос модели уже выполняется | Дождаться; отмена отправленного запроса не обещается |
| Нужен ключ | Для сохранённых провайдера и адреса нет ключа в памяти | Добавить ключ в настройках |
| Готово | Результат проверки и завершение задания сохранены одной транзакцией | Открыть диалог |
| Ошибка | Сервис недоступен, ответ не прошёл проверку или произошёл другой сбой | Прочитать сообщение; при необходимости нажать «Повторить» |
| Прервано | Сервер остановился во время запроса; неизвестно, успел ли провайдер его обработать | Проверить сохранённые результаты и вручную решить, повторять ли запрос |
| Приостановлено | Предыдущий запрос получил ошибку ключа, доступа или квоты | Исправить причину и нажать «Возобновить очередь» |
| Отменено | Задание снято до отправки или повторной обработки | При необходимости создать новую проверку |

Повторный клик по проверке одного и того же уже ожидающего диалога не создаёт второй активный запрос. Каждое задание сохраняет версию чек-листа и настройки модели на момент создания. Изменение чек-листа не меняет уже поставленные задания. «Повторить» также использует прежний снимок; для новой модели или новых правил создайте новое задание.

Сервер выполняет один запрос одновременно. Очередь делает обработку надёжнее, но сама не ускоряет ответ модели. Счётчики раздела относятся ко всей истории; таблица показывает последние 300 заданий.

В разделе также видно состояние самого обработчика. При временной ошибке локальной базы он продолжает проверять доступ; полученный ответ модели сохраняется в памяти до записи без нового AI-запроса. Пока сохраняется ответ, сервер лучше оставить работающим. Если обработчик остановлен или связь с сервером потеряна, интерфейс показывает отдельное сообщение вместо обычного ожидания. Подробности исправления — `QUEUE_RECOVERY.md`.

Ошибки HTTP 429 обычно связаны с квотой, 401/403 — с ключом или доступом, 503 — с временной недоступностью провайдера. Это не означает потерю диалога или предыдущей оценки.

## 7. Резюме и рекомендации

«Суть разговора» содержит запрос клиента, действия оператора и фактический результат. Статусы «вопрос решён» и «ожидается продолжение» различаются: передать проблему специалистам не значит уже решить её.

«Основания резюме» раскрывает цитаты. Каждая рекомендация относится к конкретному нарушенному критерию и содержит проблему, совет и доказательство. Советы не должны придумывать комиссии, сроки и правила продуктов.

Проверка схемы не гарантирует правильного смысла. Например, при тестировании ru-003 модель описала вопрос как нерешённый, но выбрала «ожидается продолжение». Статус резюме пока нельзя исправить через апелляцию критерия: сверяйте его с текстом и не используйте автоматически для закрытия обращений. Текущие результаты новой версии описаны в `UPDATE_VALIDATION.md`.

Резюме и рекомендации принадлежат исходному AI-анализу. Если проверяющий затем изменил оценку, они не переписываются молча; интерфейс напоминает об этом. Старые проверки, созданные до обновления, резюме не имеют — оно появится после новой AI-проверки.

## 8. Доказательства и аудио

Нажмите на цитату: приложение выделит нужную реплику или участок и прокрутит только панель переписки. Если бот и события скрыты, они будут показаны для просмотра доказательства. Реплики бота дают контекст, но не засчитываются как действия оператора.

У звонков есть плеер и ссылка на запись. ISO-метки исходного транскрипта сохранены. Точная точка отсчёта записи не подтверждена, поэтому автоматический точный переход к секунде аудио не заявляется. По одному тексту нельзя уверенно оценивать дикцию и интонацию.

## 9. Апелляция и решение

1. Нажмите «Оспорить оценку» у критерия; для незаполненного пункта — «Заполнить при пересмотре».
2. Укажите, с чем не согласны, и номера важных реплик.
3. Сохраните обращение.
4. Отдельным действием нажмите «Рассмотреть».
5. Подтвердите или измените ответ, обязательно объясните причину.
6. Система пересчитает итог по версии чек-листа исходной проверки. Исходный ответ и история решений останутся доступными.

Для демонстрации авторизации нет: роль проверяющего показывается отдельным действием, а не настоящей системой прав доступа.

## 10. Редактирование чек-листа

Можно менять название, описание, вес, ответы, шкалу, секцию и признак грубой ошибки; добавлять или удалять критерии. В описание нужно включить понятное условие N/A.

Для бинарного критерия ответы: `Да, Нет` либо `Да, Нет, N/A`. Для числового: например `0, 5, 10, 15, 20, N/A`. Максимальная числовая ступень определяет максимум шкалы. Флаг грубой ошибки имеет нулевой вес.

«Сохранить версию» создаёт новый чек-лист. Готовые оценки не меняются: они помечаются как рассчитанные по старой версии. Запустите новую проверку, чтобы применить новые правила.

## 11. Баллы и экспорт

Да даёт полный вес, Нет — ноль, числовая оценка нормализуется на максимум шкалы. N/A исключается, остальные веса пропорционально приводятся к 100. Итог округляется до двух знаков. Грубая ошибка — отдельный флаг, без автоматического обнуления.

Если хотя бы один критерий ещё не оценён, итог отсутствует. Система не заполняет пробелы удобными предположениями.

Кнопка экспорта в правом верхнем углу сохраняет JSON со всеми оценками, снимками чек-листов, резюме, рекомендациями и решениями. Ключ модели в экспорт не входит.

Для сдачи организаторам используется отдельный раздел **«Сдача жюри»**: он формирует Results JSON 1.0 с исходными AI-оценками, без наложения ручных апелляций. Все ID сохраняются; неоценённые диалоги имеют status=error. Подробнее — `SUBMISSION.md`.

## 12. Минимальная репетиция перед защитой

1. Откройте один заранее проверенный пример и объясните баллы, N/A и цитаты.
2. Покажите новое задание в очереди и продолжение обработки после обновления страницы.
3. Покажите резюме с реальным итогом и рекомендацию по одному нарушенному критерию.
4. Подайте апелляцию и примите решение.
5. Измените критерий, сохраните версию и примените её.
6. Объясните, где использована готовая модель, а где работают написанные нами проверки и расчёты.
