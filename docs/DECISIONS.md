# Решения и открытые вопросы

## Архитектурные решения

1. Python standard library + SQLite + самостоятельный HTML/CSS/JS. Одна команда запуска и отсутствие установки пакетов упрощают демонстрацию на другом компьютере. При большом числе пользователей встроенный HTTP-сервер потребуется заменить сервером приложения.
2. Чек-лист передаётся модели как данные, а не встраивается неизменным текстом в оценщик. Старые оценки хранят свой снимок конфигурации.
3. Баллы и веса рассчитываются кодом, а не арифметикой модели. Недопустимый ответ не исправляется молча на ближайшую ступень.
4. Цитата должна совпадать с сообщением по исходному индексу. Проверка текста не заменяет проверку того, доказывает ли он вывод.
5. Исходная оценка неизменяема. Решение апелляции накладывается отдельно, с причиной и временем. Итог пересчитывается по исходной версии чек-листа данной проверки.
6. Модель не подменяется правилами при ошибке сети или отсутствии ключа. Режим правил явно обозначен, непроверенные критерии не получают выдуманных значений.
7. Адрес API данных и ключ модели не публикуются. Публичный репозиторий содержит код и инструкции, а данные импортируются локально.
8. Для Results JSON 1.0 создан отдельный экспорт с исходными AI-ответами. Ручные решения не накладываются на результаты для сравнения; они сохраняются в обычной истории. Ошибка обработки передаётся status=error, а не N/A или нулём.
9. Схема 1.0 фиксирует восемь критериев, веса, типы и разрешённый null. Несовместимый пользовательский чек-лист блокирует экспорт; актуальная оценка не подменяется старой версией или удобным значением.

## Что требуется уточнить для качества

- Точная численная метрика близости к Ground Truth не раскрыта. В чате 7 ноября в 16:10 представитель указал сравнение по каждому критерию; PDF дополнения требует также итог и отдельный флаг грубой ошибки.
- Как трактовать прощание без итога/предложения помощи? В исходном тексте указаны оба условия.
- Является ли сообщение об ограничении конкретного счёта без подтверждённой идентификации раскрытием конфиденциальной информации по К8?
- Где официальная база знаний для проверки тарифов, условий продуктов и путей в приложении?
- Какова точная привязка времени в ISO-транскрипте к началу аудиозаписи?
- Какая политика для ошибок автоматической транскрипции и обезличивания в звонках?

## Как представить работу для рекрутмента

Показывать решения, их причины и проверяемые результаты: реальные метрики по языкам и критериям, обнаруженные ошибки, воспроизводимый запуск, историю пересмотров. В портфолио указать собственный вклад и использование AI-инструментов. Победа и предложение работы не являются результатами, которые продукт может гарантировать.
